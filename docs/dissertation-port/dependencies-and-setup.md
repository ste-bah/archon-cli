# Dependencies & Getting Started

Everything below was read directly from the repo (`feat/marker-server-parallel-ingest`).
Versions, paths, and env vars are authoritative as of this branch.

---

## 1. Rust / build

- **Toolchain:** edition **2024**, MSRV **rust 1.86** (`Cargo.toml → [workspace.package]`).
  Older toolchains hard-fail; `rustup update stable`. (Note: `docs/getting-started/installation.md`
  says "1.85+"; the workspace requires 1.86 — treat 1.86 as authoritative.)
- **Binary:** `archon` (`[[bin]] path = "src/main.rs"`), ~66 MB release.
- **Build:**
  ```bash
  git clone https://github.com/ProfessorVR/archon-cli
  cd archon-cli
  cargo build --release --bin archon        # → target/release/archon
  ```

### CRITICAL build requirement — `LIBCLANG_PATH`

The workspace links **CozoDB** (`cozo-ce`, RocksDB + SQLite backends) and
**`rust-rocksdb`**. RocksDB's FFI is generated by **bindgen**, which needs
**libclang** at build time. Without it the Cozo/RocksDB step fails to find
`libclang.so`.

| OS | Install | Export |
|---|---|---|
| Ubuntu / Debian / WSL2 | `sudo apt install -y llvm-18 libclang-18-dev clang-18` | `export LIBCLANG_PATH=/usr/lib/llvm-18/lib` |
| Fedora / RHEL | `sudo dnf install -y clang-devel llvm-devel` | `export LIBCLANG_PATH=$(llvm-config --libdir)` |
| Arch | `sudo pacman -S clang llvm` | usually auto-detected |
| macOS | libclang ships with Xcode CLT (`xcode-select --install`), or `brew install llvm` | `export LIBCLANG_PATH="$(brew --prefix llvm)/lib"` |

> `scripts/install-system-deps.sh` installs the C toolchain, `pkg-config`,
> `libssl-dev`, and `git` — but **not** llvm-18/libclang; add it separately.

**WSL2 gotcha:** on < 8 GB RAM, parallel rustc across the ~36-crate graph
OOM-kills the WSL VM. Build with `-j1` (`cargo build --release --bin archon -j1`,
~3–4 min). Native Linux/macOS don't need this.

## 2. Embedded data store (no external DB service)

Archon is fully in-process — nothing to stand up:

- **CozoDB** (graph/relational) over **RocksDB** + a bundled SQLite backend,
  wrapped by the `archon-cozo` crate. The live DB is a single file
  `.archon/archon-data.db` with an `fd-lock` write lock.
- **Embeddings** via **fastembed** (ONNX Runtime downloaded as a prebuilt binary;
  models pulled from HuggingFace over rustls). Vector index uses `hnsw_rs`.
  Embedding is **CPU-only** this round (~0.5 GB RAM), not a GPU consumer. Vectors
  live at `.archon/doc-vector-store/`.

RocksDB + SQLite + fastembed-onnx are all linked into the `archon` binary. No
Postgres/Chroma/Redis to run.

## 3. Python Marker stack (real bounding boxes)

Marker is the provenance-critical PDF path. It runs as Python, driven by Archon
over a subprocess sidecar or a persistent HTTP server. **Validated versions:**
`marker-pdf 1.10.2`, `surya-ocr 0.17.1`, Python 3.11/3.12. There is no
`requirements.txt` — create the venv by hand.

**NVIDIA / CUDA host (incl. Blackwell / RTX 50-series → cu128):**
```bash
python3.11 -m venv ~/.venv-marker
~/.venv-marker/bin/python -m pip install --upgrade pip
~/.venv-marker/bin/python -m pip install torch --index-url https://download.pytorch.org/whl/cu128
~/.venv-marker/bin/python -m pip install marker-pdf==1.10.2 surya-ocr==0.17.1
~/.venv-marker/bin/python -c "import torch; print(torch.cuda.is_available())"   # True
```

**Apple-Silicon host (Metal / MPS):**
```bash
python3.11 -m venv ~/.venv-marker
~/.venv-marker/bin/python -m pip install --upgrade pip
~/.venv-marker/bin/python -m pip install torch marker-pdf==1.10.2 surya-ocr==0.17.1
~/.venv-marker/bin/python -c "import torch; print(torch.backends.mps.is_available())"  # True
```

**Device selection:** auto `cuda → mps → cpu`; override with `--device` or
`TORCH_DEVICE`. In policy, `marker_device = "auto"` (default).

**Persistent server (recommended for bulk corpora — no per-doc model reload):**
```bash
~/.venv-marker/bin/python3.11 scripts/archon_marker_server.py --device cuda --host 127.0.0.1 --port 8010
curl -s http://127.0.0.1:8010/health   # {"status":"ok","device":"cuda","models_loaded":true}
```
Select it by setting `marker_url` in policy (it overrides `marker_sidecar`). The
server reads the PDF from its own filesystem (only the path is sent, never
bytes), so it must share Archon's filesystem / identical absolute paths.

## 4. VLM — image descriptions (Ollama + qwen2.5vl)

Optional, off by default; adds a natural-language *description* of each figure
(distinct from OCR text extraction). Recommended model: **`qwen2.5vl:7b`**
(~6 GB; works on old and current Ollama, unlike `llama3.2-vision`). Policy points
at `http://localhost:11434`.

```bash
# Standard (has sudo):
curl -fsSL https://ollama.com/install.sh | sh

# Locked-down / no-sudo (manual tarball — the current asset is a .tar.zst):
curl -L https://github.com/ollama/ollama/releases/latest/download/ollama-linux-amd64.tar.zst -o ollama.tar.zst
mkdir -p ~/.ollama-bin && tar --use-compress-program=unzstd -xf ollama.tar.zst -C ~/.ollama-bin
export PATH="$HOME/.ollama-bin/bin:$PATH"

# Serve + pull:
ollama serve &
ollama pull qwen2.5vl:7b
ollama ps
```

**VRAM reality:** the resident size is dominated by KV cache — ~22 GB @32K ctx,
~14 GB @4K. On ≤8 GB hosts, run the VLM on **CPU** (`OLLAMA_NUM_GPU=0`) so Marker
owns the GPU; text-only docs never load the VLM (Ollama lazy-loads). Marker exits
and frees its VRAM before enrichment, so within one document Marker-VRAM and
VLM-VRAM never coexist.

## 5. OCR engines

Three local layers:

- **poppler-utils** — `pdftotext` (text-layer extraction / no-Marker fallback),
  `pdfinfo`, `pdftoppm` (whole-document render for scanned PDFs), `pdfimages`.
  The unified PDF path needs all of them. Install via
  `scripts/install-system-deps.sh` (`poppler-utils` / `poppler` / `poppler-tools`).
- **rapidocr-onnxruntime** — image OCR, the working fallback (Python).
  `~/.venv-marker/bin/python -m pip install rapidocr opencv-python`
  (older envs: `rapidocr-onnxruntime`, module `rapidocr_onnxruntime`).
  **Interpreter resolution matters:** Archon's OCR path (`ocr/rapid.rs`) picks
  the python in this order — `ARCHON_RAPIDOCR_PYTHON` → `~/.archon-marker-venv/bin/python`
  → `python3`. So rapidocr must live on whichever that resolves to. If your marker
  venv is `~/.venv-marker`, either set
  `ARCHON_RAPIDOCR_PYTHON=~/.venv-marker/bin/python` **or** symlink
  `ln -s ~/.venv-marker ~/.archon-marker-venv`.
- **tesseract** (optional) — `tesseract-ocr` (apt) / `tesseract` (brew). Gated by
  `[policy.workers] ocr`.

## 6. Policy config (`.archon/policy.toml`)

Template: `.archon/policy.example.toml` (safe to commit); your real
`.archon/policy.toml` is gitignored. Load order (later wins):
`/etc/archon/policy.toml` → `~/.archon/policy.toml` → `<workspace>/.archon/policy.toml`.

> `[policy.workers] vlm` must be `allow-local` **in addition to**
> `[policy.docs.vlm] enabled = true` — a `deny` there silently overrides the VLM.

Minimal working block (CUDA host, warm Marker server + Ollama VLM):
```toml
[policy.workers]
ocr = "allow-local"
embedding = "allow-local"
vlm = "allow-local"          # required for the VLM to run
web_fetch = "allow-local"

[policy.docs.pdf]
extract_embedded_images = true
scan_detector = "union"
image_enrichment_workers = 1
marker_sidecar = "/ABS/PATH/archon-cli/scripts/archon_marker_sidecar.py"
marker_python  = "/home/you/.venv-marker/bin/python3.11"
marker_url     = "http://127.0.0.1:8010"   # persistent server; overrides sidecar
# marker_device = "auto"
# marker_memory_budget_mb = 6000

[policy.docs.vlm]
enabled  = true
mode     = "local"
provider = "ollama"

[policy.docs.vlm.ollama]
endpoint     = "http://localhost:11434"
model        = "qwen2.5vl:7b"
timeout_secs = 120
```

> Leaving both `marker_sidecar` and `marker_url` unset → silent fallback to
> `pdftotext` (text only, **no bboxes**).

## 7. Step-by-step runbook

```bash
# (1) System deps (build + poppler + tesseract)
sudo scripts/install-system-deps.sh                     # Linux; macOS: run WITHOUT sudo
# libclang for the Cozo/RocksDB build (NOT covered above):
sudo apt install -y llvm-18 libclang-18-dev clang-18
export LIBCLANG_PATH=/usr/lib/llvm-18/lib

# (2) Build archon
cargo build --release --bin archon                      # add -j1 on WSL2 (<8 GB RAM)
sudo cp target/release/archon /usr/local/bin/           # or: cargo install --path .

# (3) Marker venv — CUDA variant (Apple variant: drop the cu128 index-url)
python3.11 -m venv ~/.venv-marker
~/.venv-marker/bin/python -m pip install torch --index-url https://download.pytorch.org/whl/cu128
~/.venv-marker/bin/python -m pip install marker-pdf==1.10.2 surya-ocr==0.17.1

# (4) Ollama + model + serve
curl -fsSL https://ollama.com/install.sh | sh           # or the no-sudo tarball (§4)
ollama serve &
ollama pull qwen2.5vl:7b

# (5) rapidocr on the marker interpreter
~/.venv-marker/bin/python -m pip install rapidocr opencv-python
ln -s ~/.venv-marker ~/.archon-marker-venv              # or export ARCHON_RAPIDOCR_PYTHON

# (6) Write .archon/policy.toml (see §6)
cp .archon/policy.example.toml .archon/policy.toml      # then edit paths

# (6b) Optional: start the warm Marker server (matches marker_url)
~/.venv-marker/bin/python3.11 scripts/archon_marker_server.py --device cuda --port 8010

# (7) Ingest (--jobs auto derives workers from FREE VRAM; --yes skips prompts)
archon docs ingest <dir> --jobs auto --yes

# (8) Verify integrity (expect 0 mismatch)
archon docs verify-integrity
```

For the style analytics side (pure Rust, no extra deps):
```bash
archon style train samples/*.md --name mystyle --genre academic
archon --output-style mystyle "...prompt..."
```

## 8. Tunable env vars

| Env var | Default | Purpose |
|---|---|---|
| `LIBCLANG_PATH` | (unset → bindgen probes) | **Build-time.** libclang for the RocksDB/Cozo bindgen step. Repo uses `/usr/lib/llvm-18/lib`. |
| `TORCH_DEVICE` | auto (`cuda→mps→cpu`) | Forces the Marker/torch device; set before importing marker. |
| `ARCHON_MARKER_GPU_TIMEOUT_SECS` | 900 | GPU Marker convert bound (a hang → ladder falls to CPU). |
| `ARCHON_MARKER_CPU_TIMEOUT_SECS` | 3600 | CPU Marker convert bound (generous last rung). |
| `ARCHON_OCR_TIMEOUT_SECS` | 120 | One OCR subprocess (tesseract / RapidOCR / poppler per page). |
| `ARCHON_PDF_RENDER_TIMEOUT_SECS` | 1800 | Whole-document `pdftoppm` render (all pages, one invocation). |
| `ARCHON_PDF_IMAGE_TIMEOUT_SECS` | 600 | Per-image enrichment backstop; a wedged image SKIPs, never fatal. |
| `ARCHON_RAPIDOCR_PYTHON` | `~/.archon-marker-venv/bin/python`, else `python3` | Interpreter for RapidOCR image OCR (must have rapidocr). |
| `ARCHON_RAPIDOCR_MIN_SCORE` | 0.55 | Min confidence for a RapidOCR line. |
| `ARCHON_OCR_ENGINE` | (unset) | `rapidocr` prefers RapidOCR; `tesseract` disables the RapidOCR fallback. |
| `OLLAMA_NUM_GPU` | (Ollama default) | Set `0` to force the VLM onto CPU so Marker keeps the GPU (≤8 GB hosts). Ollama env, not Archon. |
| `ANTHROPIC_API_KEY` / `ARCHON_API_KEY` | (unset) | Anthropic auth for the LLM side (or OAuth via `archon auth login`). |

## 9. Platform-specific gotchas

- **WSL2 build:** `-j1` is effectively mandatory on < 8 GB RAM; `libclang`
  (llvm-18) is a separate install.
- **WSL2 CUDA:** free-VRAM detection uses `nvidia-smi` — the Windows-side wrapper
  must be on the WSL `PATH` (normally via `/usr/lib/wsl/lib`).
- **WSL2 background jobs:** the persistent Marker server / `ollama serve` are
  long-lived; WSL reaps background processes when the last session closes and can
  idle-shut-down the VM. Set `[wsl2] vmIdleTimeout` in `%UserProfile%\.wslconfig`
  (raise/disable), or run long jobs in the foreground.
- **macOS non-login shells:** `/opt/homebrew/bin` is often absent from a non-login
  shell's `PATH`, so `poppler` / `ollama` "vanish" when Archon spawns subprocesses.
  Use a login shell (`bash -lc`) or absolute paths. A signed binary copied to an
  external volume may need `codesign --force --sign - <archon>`.
- **Apple MPS:** unified-memory pressure is soft (no catchable OOM); if surya/MPS
  is flaky, run the Marker server with `--device cpu`. `--jobs auto` caps
  unified-memory hosts to ≤2 workers.
