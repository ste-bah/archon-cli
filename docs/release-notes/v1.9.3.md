# v1.9.3

Patch release: eleven deleted TUI screens adjudicated one at a time, a
microphone that actually records and a voice to answer with, a write that has to be backed by a read, and
a mutation-preflight walk that had made large repositories unusable.

## Fixed

- **`TaskCreate` and every other mutating tool call no longer hang on a large
  repository.** The preflight that snapshots the working tree walked every file
  under the working directory and SHA-256'd it, twice per mutating call,
  ignoring `.gitignore` — so on a checkout with a populated `target/` it never
  finished. It now walks the ignore-aware tree, skips `.git`, and stops at a
  bounded entry count. A one-file directory took 954 ms and a real checkout
  never returned; the same checkout now takes 3.4 s.
- **Bash puts its child in a session of its own.** The containment was named for
  process groups and never created one: the child inherited the caller's group,
  so the cleanup path signalled `-<child pid>`, which usually named no group at
  all and returned `ESRCH` — read as "already gone". When that pid did collide
  with a real group it named processes archon does not own. macOS refused it
  with `EPERM`, which is the kernel reporting the bug.

  A process group turned out to be the wrong unit (#197). It still inherits the
  controlling terminal, so a command that wants an answer opens `/dev/tty`
  directly and gets one wherever stdin points — and from a background group that
  raises `SIGTTIN`, which *stops* the child rather than failing it: state `T`,
  pipes still held, nothing there to answer. A `git diff HEAD | patch -p1` that
  could not place a hunk asked `File to patch:` and held that state for thirty
  minutes, freezing an eleven-item parallel wave. No timeout caught it, and none
  should have: the command was not slow, so a deadline strict enough to catch it
  would kill honest long builds instead. `setsid` leaves no controlling terminal
  at all, so the open fails with `ENXIO`, the command errors out promptly, and
  the agent can pick a different one. It is also strictly stronger than the
  process group it replaces — a session is a new group with the child as leader,
  so `kill(-pgid)` still reaches exactly this command's descendants.
- Bash reports a signalled command as `128 + signal` instead of `-1`, so a
  process killed by `SIGKILL` is distinguishable from one that failed to start.
- Overlays clear the region they draw into, use the configured theme, and draw
  a selection marker. Ten screens had between them three `Clear` calls, one
  theme reference and no selection rendering at all, so arrow keys looked like
  dead keys and modals showed the conversation through their own gaps.

## Added — the screens

#189 Phase 0 deleted eleven TUI screens as redundant with the slash commands
they duplicated. Eight are back and wired to a real code path; three stay
deleted, each for its own stated reason rather than one sentence applied to
all eleven.

| Command | Overlay |
|---|---|
| `/model` | provider/model picker, filterable by typing |
| `/theme` | theme list, cursor on the applied one |
| `/config` | every setting, read-only ones marked |
| `/hooks` | registered hooks by event, command and source |
| `/permissions` | mode and every rule, grouped by effect |
| `/memory files` | the `ARCHON.md` hierarchy in force |
| `/fork-at` | branch points, one row per message |
| `/voice` | live microphone level and last transcription |
| `/context` | ranked per-message token attribution |

Bare form opens the overlay; every existing argument form is unchanged, so
`archon -p` output is byte-identical. Enter types the slash command that
applies the change rather than applying it — the command is the one place that
validates and persists, and three of these screens shipped with a
`toggle_selected` that mutated a copy nothing downstream read.

`/permissions`, `/memory files` and `/context` are read-only with no action
key, because no runtime setter exists behind them.

Not restored: `session_stats` (never had a `render`; superseded by a session
projection), `session_browser` (`/resume`'s picker already exists),
`mcp_view` (a second MCP overlay behind a store trait with no implementor,
duplicating the one `/mcp` opens).

## Added — voice

- **A real microphone.** Production built a `MockAudioSource` seeded with a
  second of zeroes, in *both* branches of a check that logged "real audio
  device detected". Voice input never failed and never worked: it recorded
  silence, the VAD discarded it, and nothing said so. `CpalAudioSource` records
  from the device, mixes to mono, and resamples to 16 kHz.
- Voice that cannot run says so at startup and does not start a pipeline.
- The capture overlay draws the measured peak against the VAD threshold, so
  "I spoke and nothing happened" is answerable on screen.
- `audio-capture` is a default feature, covering both the microphone and the
  speaker. On Linux it needs `libasound2-dev`, which
  `scripts/install-system-deps.sh` now installs.

## Added — archon speaks

Replies can be read aloud. `Ctrl+P` toggles it live, `/voice speak on|off` does
the same by typing, and the `/voice` overlay shows which state you are in — a
toggle whose only evidence is whether the *next* reply speaks is one you find
out about too late.

The default voice is **Kokoro-82M**, run locally through `kokoro-fastapi`. It is
a neural model trained on real speech, not a formant or concatenative
synthesiser, and it does not sound like one. `kokoro-fastapi` speaks the OpenAI
`/v1/audio/speech` protocol deliberately, so one client reaches both it and
OpenAI — the difference is a URL, a model and a voice rather than any code.

Speaking is independent of listening: a machine with no microphone can still
read answers out. Playback goes through cpal on all three platforms (WASAPI,
CoreAudio, ALSA) and is resampled to whatever rate the output device runs at,
because a device does not negotiate.

A reply is spoken once the turn finishes rather than delta by delta, trimmed at
a sentence end past about a thousand characters, and one at a time. A synthesis
failure costs that reply and not the session.


## Added — what is filling the context window

`/context` opens a ranked list of which messages account for the window, with
each one's share and what the listed rows add up to. The per-message
attribution has been computed since #189 Phase 3 and exactly one number of it
reached the screen — `top 92k`, the size of the worst message, with no way to
learn which message that was.

## Added — read before write

`Edit`, `Write` and `NotebookEdit` are refused when the agent has not read the
file in this session, or when the file changed on disk since it did. `Bash` is
not checked: a shell command can write anywhere and names no path.

```toml
[filesystem]
read_before_edit = "block"   # or "warn", or "off"
```

## Added — sessions

- `/fork-at <n>` forks through an earlier message, keeping `0..=n` and leaving
  the source session untouched. `/fork` copies the whole log; there was no way
  to fork at an earlier point at all.
- `/feedback good|bad|clear [note]` rates the last assistant message. The
  rating goes to a sidecar relation keyed by message id and never into the
  message log, so it cannot reach model context — a model that could see its
  last answer was rated badly would start writing for the rating. The rating
  records a digest of the message it was made about, so a compaction that
  renumbers the log cannot reattribute it to different text.
- Session projections fold the event log once and cache the result with the
  sequence number they folded through, so a repeated question about an idle
  session costs one lookup instead of a rescan. `/status` reads one.

## Security

- Spilled tool output is written with restrictive permissions rather than
  inherited ones: `0700`/`0600` at creation on Unix, broken inheritance plus a
  single full-control entry on Windows. These files hold whatever the tool
  produced — a repository-wide grep, an HTTP response body, a config — and were
  previously created with whatever the directory happened to grant. Each is
  written with `create_new` and a random suffix, so a spill can never overwrite
  an existing file.

## Removed

- The `feedback` skill. It answered `/feedback <message>` with "Feedback
  recorded: …" and recorded nothing — no store, no file, no request.
  `/feedback` is now a primary handler that writes to the session store.

## Upgrade notes

> **A write to a file the agent has not read is now refused.** This is the
> default. An agent that writes files it never opened — a generator, a
> formatter driving `Write` over a tree — will be blocked. Set
> `[filesystem].read_before_edit = "warn"` to log the reason and allow it, or
> `"off"` to restore the previous behaviour. `Bash` is unaffected.

> **`voice.hotkey` now defaults to `"ctrl+v"`.** It read `"ctrl+shift+v"`,
> which described a key that had never been bound. The value is reported by
> `/voice` and read by nothing else; the binding is fixed at `Ctrl+V`.

> **Building on Linux needs `libasound2-dev`** (`alsa-lib-devel` on
> Fedora/RHEL) now that microphone capture is a default feature.
> `scripts/install-system-deps.sh` installs it. To build without it:
> `cargo build --no-default-features` for `archon-tui`, which disables voice
> input and nothing else.

> **`/feedback` means something different.** It rates a message rather than
> submitting a report. The skill it replaces never submitted anything.
