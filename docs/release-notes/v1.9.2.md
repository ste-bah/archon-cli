# v1.9.2

Patch release: trustworthy Plan Mode approval and lifecycle, explicit `/plan`
exit controls, durable plan-linked work, and registered-skill autocomplete.

## Fixed

- Plan Mode records the previous permission mode and restores it through the
  safe restoration path. Missing state and unavailable `bypassPermissions`
  both fall back to `default`.
- `/plan off`, `/plan exit`, and `/plan done` exit directly to `default`.
  Unknown `/plan` arguments fail loudly without changing mode.
- A structured `ExitPlanMode` submission persists the candidate plan and waits
  for approval. Rejection keeps Plan Mode active; approval and approved edits
  restore the permitted execution mode.

## Added

- `/plan open` creates or edits a plan document under
  `.archon/plans/<plan-id>.md`. Tool interceptions are recorded separately in
  `.archon/plan-audit/<session-id>.md`.
- Approved plan steps materialize as durable task records with dependencies,
  required evidence, completion evidence, and reconciliation state. Plan-linked
  tasks rehydrate after restart when the same session and plan store reopen.
- `[context].plan_model` can override the model used while Plan Mode is active.
- Registered canonical skills appear in slash autocomplete. Primary commands
  sort first, skills sort second, and rows are labelled `[command]` or `[skill]`.

## Security and trust boundary

- Plan Mode limits tools to the canonical Plan-safe allowlist and blocks
  working-tree mutations outside approved execution.
- Subagents cannot enter or exit Plan Mode.
- Approval authority is process-private and bound to its plan store and
  session. Test completion accepts only signed, independently verified test-run
  evidence; unsupported or unsigned evidence fails closed.
- A skill with the same canonical name as a primary command is omitted from
  autocomplete. Startup logs
  `skill '/{skill}' is shadowed by primary command '/{primary}'; primary dispatch wins`.

## Configuration

```toml
[context]
# plan_model = "claude-sonnet-4-6"
noninteractive_plan_approval = "approve" # set "reject" to fail closed
```

When `plan_model` is unset, Plan Mode uses the active session model. In a
noninteractive session, `noninteractive_plan_approval = "reject"` rejects a
structured exit when no approval channel exists; the default remains
`"approve"`.

## Upgrade notes

- Structured `ExitPlanMode` submissions require approval. Explicit user commands
  `/plan off`, `/plan exit`, and `/plan done` remain direct exits to `default`.
- Only plan-linked tasks persist and rehydrate. Unrelated manually created tasks
  remain process-scoped.
- Skills are discovered when a session starts. Restart Archon after adding or
  editing a `SKILL.md` file. Plugin bundles must install their skills into the
  standard project or user roots; bundle directories are not scanned directly.

## Verification

- Every Plan lifecycle/trust task and the skill-autocomplete task passed all six
  physical development gates, including executed end-to-end smoke tests and
  independent Sherlock reviews.
- The final Plan smoke exercised approval, durable task materialization,
  authoritative test evidence, reconciliation, and safe restoration.
- Skill autocomplete validation covered production registry discovery,
  primary/skill ordering and labels, aliases, shadow omission, the exact startup
  warning, and an ignored production-backed smoke that selected and passed one
  test.

## Known limits

- Concurrent plan-audit writes are serialized within one Archon process; no
  stronger ordering is promised across separate processes.
- Restart rehydration requires reopening the same session and its durable plan
  store.
