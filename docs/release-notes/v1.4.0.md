# Archon v1.4.0 — Self-learning world model and `archon draft`

v1.4.0 turns the JEPA world model from a scaffold into something that actually
learns, adds the `archon draft` FCDP pipeline as a first-class Rust crate, and
closes a long run of correctness work on the agent catalog and CI.

`/draft` brings the slash primary count to 85.

## World model — the encoder now learns (#106)

Before this release the JEPA "training" run fitted the predictor, auxiliary
heads and transition model by closed-form least squares over frozen features.
`max_epochs` and `learning_rate` were declared, defaulted, validated, and read
by no code. The representation was identical before and after a training run.

- `candle` is a default feature, so the shipped CPU build has autodiff. `cuda`
  and `mlx-metal` stay opt-in and `--no-default-features` still builds lean.
- Encoders hold tensors and are trained by gradient descent, consuming
  `max_epochs` and `learning_rate`.
- Stop-gradient on the target branch, and the EMA target update moved inside
  the training loop rather than being applied once at initialisation.
- `training_losses` is the differentiable objective rather than a score over
  fixed encodings, and `collapse_report` is a live training gate that can now
  actually fire.
- Encoders gained real capacity: two `latent_dim x latent_dim` layers with a
  GELU between them and a residual path around them, roughly 295k parameters
  each at the default 384. The previous per-dimension form could only rescale
  each dimension in place — output `i` depended solely on input `i` — so it
  could not combine two features or rotate the embedding basis toward a
  direction worth predicting.

### Encoder input

- `TraceWindow` and `TraceAction` carry an optional dense embedding, and both
  training entry points supply one: `archon world train-jepa` and the
  background trainer tick. Where no adapter is available the encoder falls back
  to hashing excerpt text into `latent_dim` buckets, as before.
- `source` and `action_kind` are closed enums and now own a reserved dimension
  each; `provider`, `agent` and `model` are open strings and get their own
  small reserved sub-blocks. Previously all five were hashed across the whole
  vector alongside an open English vocabulary.
- Unbounded identifiers are no longer hashed in at all — session id, anchor row
  id, action ref, evidence ids, prior plan and memory ids. Each value occurs
  once and never recurs, so it could not generalise; it only consumed bucket
  capacity. Graph *counts* and the evidence *source* are kept.
- An embedding of the wrong width, or one carrying a non-finite value, is
  treated as absent. Two code paths previously disagreed about this, so such a
  window kept neither the embedding nor the hashed text.

### Live loop and lifecycle

- A pre-turn advisory hook runs in the live agent path using pre-call features
  only, fail-open and within a latency budget, with concrete interventions
  wired to the guardrail risk tiers.
- Post-turn outcome capture is automatic: predicted, actual, surprise, with no
  manual `record-outcome`.
- Candidates are evaluated on write inside the trainer tick, shadow-evaluated
  against live traffic, auto-promoted on gate pass and rolled back on
  regression.
- `archon world status` reports trainer liveness and staleness, and renders
  `Last eval: none` / `Active model: none` as degraded states rather than
  neutral facts. The contradictory `Selected backend: metal` beside
  `Backend fallback: backend_unavailable` is gone.
- `archon world eval` defaults to the most recent candidate instead of erroring
  that a required argument was optional.
- Candidate actions are ranked by predicted outcome, steering toward a safer
  action rather than only blocking a dangerous one.

**Not yet measured.** Whether the learned representation beats the existing
nearest-neighbour baseline is an empirical question that needs a corpus
(1,000 rows / 50 sessions / 7 observed days) and has not been answered. The
`archon world eval` gates are the instrument.

## `archon draft` — FCDP pipeline

- New `archon-draft` crate porting the former Python FCDP orchestration to
  Rust, with the P0–P6 gate pipeline.
- `archon draft` imports the FCDP provenance chain into the CozoDB store, and
  links drafts to ingested corpus provenance (reaches-source).
- `/draft` is available in-session from the TUI, streaming `archon draft`.
- Judge verdict extraction is hardened against format drift, and the token
  budget retry-escalates with a stderr diagnostic when it hits the ceiling.
- The `scripts/fcdp` Python orchestration is removed.

## Agent catalog

- Catalog resolution is ordered before queries.
- Reconciled snapshots are published, partial bulk discovery loads are
  preserved rather than discarded, accepted bulk records are reported, and
  invalid bulk metadata is rejected per entry instead of failing the load.
- Dependency errors are compact and unresolved dependencies are reported.

## Repository health

- Every file is under the 500-line ceiling; both file-size gates report zero
  offenders.
- Six deterministic test failures on `main` are fixed, and the unbounded
  `AgentEvent` gates that contradicted TASK-AGS-102 are retired.
- Source, fixtures and generated docs are pinned to LF, ending a class of
  CRLF-dependent test failures on Windows checkouts.
- The tree is `cargo fmt` clean under edition 2024.
- `output_config.effort` is enabled for current models, and
  `build_request_body` is exposed.
