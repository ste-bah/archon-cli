# v1.5.1

A patch release. Three defects that made the application unusable in ordinary
operation, all found by running it rather than by reading it.

## Cancelling a turn wedged the session

Topology admission takes a spawn's live-agent slot and a write's path claims at
admission time and releases them in `on_tool_run_outcome`. A cancelled attempt
never reaches that callback, so the claims leaked — and every later write in the
session was then refused as conflicting with a holder that no longer existed.

One Ctrl+C or double-Esc broke the session until the process restarted.
Cancelling a long turn is normal operation, not an edge case, and there was no
release path for it on any of the paths that cancel.

Both key bindings funnel through the same `__cancel__` sentinel, so a single
release point covers them. It ends and re-begins the session, discarding an
executed prefix that describes work which did not finish, and leaves the session
tracked so the guardrail stays live for the rest of it.

The web runtime's cancel path still leaks; it is a separate surface and is not
fixed here.

## Memory recall ran unbounded on every turn

Before the provider was contacted, each turn scanned the memory store without
bound. A slash-command turn carries its whole skill template — 21 KB, ~3,200
words — and every one of the ~1,500 distinct terms became an `OR` branch. Cozo
evaluates every branch of an `Or` in full, and the wrapper then re-ran the entire
query with a **doubling** limit (256, 512, 1024 …) until the index was exhausted,
across three indexes.

Measured on a 1.7 GB store: 38 minutes of one core, with zero network activity,
before a single request went out. `recall_corrections` was worse — no limit was
expressible (`SearchFilter` had no limit field, so it passed `usize::MAX`), no
cache, and it re-ran on every tool round.

Now: at most 32 terms per query, one query per index instead of ~log2(N), a real
`limit` on `SearchFilter` (where `None` still means unbounded, so no existing
caller is silently truncated), and a bounded candidate window for the severity
re-rank in `recall_corrections`.

`inject_memories` also moves off the async executor. It had no `.await` points,
so the cancellation token was never observed and Ctrl+C could not interrupt it at
all. **Note what this does and does not achieve:** `spawn_blocking` work cannot
be pre-empted, so the scan still runs to completion on a blocking-pool thread.
The executor stays responsive and the turn stops waiting — the scan is not
aborted.

Two bugs the fix itself introduced, both caught by existing tests before release:
passing `usize::MAX` through overflowed Cozo's `k` pre-allocation and aborted in
`raw_vec`; and bounding candidates at the caller's limit starved the access-boost
re-rank, so a frequently-used memory that ranks poorly on TF-IDF could never be
surfaced. Candidates are not results.

Still unaddressed: the `NGram(1, 2)` tokenizer, whose unigrams give posting lists
close to the whole relation, and two `read_all_memories` fallbacks that have no
`k` to push down. Per-turn timing is now logged on every outcome — including the
empty one, which is the case that most resembles a hang — so the decision to
change the tokenizer can be made against a measurement.

## Shifted symbols could not be typed on a non-US keyboard

The keymap held a hardcoded US `(unshifted, shifted)` table. On a UK layout `?`
is Shift+/ and was absent from it entirely, while `@` and `~` sit on different
keys than it assumed — so those keys silently did nothing. Terminals resolve the
layout themselves and deliver the resulting character with SHIFT set, which the
table could never match.

Each printable character is now bound to itself under SHIFT and the table is
gone. Letters are deliberately excluded: crossterm normalises `Char('A')`+NONE
and `Char('a')`+SHIFT to the same hash key, so a blanket binding inserted after
the unmodified loop overwrites `CharInput('A')` with `CharInput('a')` and breaks
every capital.

Characters outside the keymap's ASCII list — `£`, `¬`, and every other layout's
symbols — now fall through to being typed, since enumerating them can only ever
move the boundary. CONTROL and ALT are excluded, so an unbound chord still does
nothing rather than typing a stray letter.

## LEANN indexer

Exclusion patterns never matched. `is_excluded` compares path *components*, so
the glob spellings the caller passed (`**/target/**`) could not equal any
component and excluded nothing — the indexer walked `target/`, `node_modules/`
and `.git/` in full. Because the caller's list was non-empty it also *replaced*
the defaults rather than extending them, losing nine more directories.

Reported: ~609,000 files into a 1.4 GB index that never completed. After the fix,
the same repository indexes 102 files and 1,206 chunks into 14 MB.

Embedding and persistence are also interleaved now, so a cancel banks the work
already done and the next run resumes; previously the whole embedding pass was
discarded. The indexer had no `tracing` calls at all across walk, chunk, embed
and write, which is why a 50-minute run was indistinguishable from a deadlock.

## Upgrading

No configuration changes. The v1.5.0 behaviour changes (Windows hook shell,
`ARCHON_DATA_DIR`) still apply and are unchanged by this release.
