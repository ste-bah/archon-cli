# v1.5.2

A patch release. It contains the Issue #115 security fixes, Issue #117 Rust
warning cleanup, memory and session correctness fixes already merged to `main`,
and security-sensitive dependency updates. It does not add a new release tag or
artifact by itself.

## Issue #115: contain Marker HTTP access

Marker's persistent HTTP server no longer accepts a client-supplied filesystem
path. At startup, `--pdf-root` is resolved and recursively scanned, and the
server freezes the canonical regular PDFs beneath it into an ID-to-path
catalogue. Requests carry an opaque, deterministic SHA-256 ID derived from the
canonical path, not that path or the PDF bytes. Nested PDFs and duplicate
basenames remain distinguishable.

Archon and the Python server use the same canonical-path hash contract. Rust
normalizes Windows verbatim drive and UNC prefixes to the ordinary path text
returned by Python before hashing. Both sides still need the same canonical path
text: run them on the same host or provide identically mounted shared canonical
paths. Restart the server after corpus additions, moves, deletions, or
replacements because its catalogue is intentionally static for the process
lifetime.

The `/convert` request model uses strict strings, rejects unknown fields, and
returns fixed safe errors instead of validation or conversion details. Page
ranges are decimal, inclusive, ordered, and capped at 1,000 pages per request.
The unauthenticated server binds to loopback by default; a non-loopback host now
requires the explicit `--allow-non-loopback` override, which adds no
authentication.

Issue #115 also covered custom security-guidance regexes. The prior ReDoS
(regexp denial-of-service) source is replaced by bounded static scans that reject
unsafe or unrepresentable structures before `re.compile`. Validation is capped
at 4,096 pattern characters and fails closed for the covered ambiguous repeated
and adjacent quantified forms.

The Linux TCP smoke test starts a real Uvicorn listener and verifies catalogue
IDs, request-schema rejection, page-range bounds, fixed conversion errors, and
the non-loopback CLI guard. Its conversion function is deliberately fake: it
does **not** load Marker or Surya production models and therefore does not prove
production GPU model loading or real document conversion.

## Issue #117: warning-free Rust targets

The full Rust workspace now compiles every library, binary, example, benchmark,
and test target without warnings. Stale imports and confirmed orphaned helpers
were removed, while test-only topology and adjudication helpers are now compiled
only for tests. Split-module imports were narrowed to the visibility their items
actually provide instead of relying on ineffective glob re-exports.

CI now runs `cargo check --workspace --all-targets --locked` with
`RUSTFLAGS=-D warnings` as a required job, so new compiler warnings fail pull
requests instead of accumulating silently.

## Memory and resumed sessions

- Full-text memory recall now bounds prompt text, query terms, and candidate
  windows. Correction recall runs once per user turn rather than once per tool
  round, while a new turn always recalls again.
- Resuming a session now continues writing conversation history and usage to the
  selected session instead of copying the conversation into a newly created
  launch row. Process-scoped topology and guardrail admission remain attached to
  the running process.
- Memory inputs and model-produced writes are bounded across extraction,
  corrections, and the memory tool. Automatic extraction uses an ordered window
  capped at 40 messages, 1,000 characters per message, and 24,000 characters
  total. Extracted rules are capped at 240 characters and other extracted
  memories at 2,000.
- Consolidation uses measured semantic distance bands: close pairs may merge,
  ambiguous pairs await bounded model adjudication, and distant pairs remain
  separate. Superseded rows are retained for provenance but filtered from normal
  recall. Serialized personality and inner-voice state is excluded from
  ordinary recall, and importance decay now charges only the interval since the
  previous consolidation rather than compounding the full age on every run.
- `/memory store` now exists, strips the documented surrounding quotes, and
  supports bounded manual storage with optional `--type` and `--importance`.
  Rule and personality-snapshot types remain unavailable for manual storage.
- When automatic consolidation changes visible memory state, the startup splash
  reports its summary; no-op consolidation remains silent.

## Dependency updates

Merged dependency PRs update:

- PR #113 initially updated `russh` 0.61.1 to 0.61.2 and `quinn-proto`
  0.11.14 to 0.11.16. This release subsequently updates the direct `russh`
  dependency to 0.62.5, which includes the remaining Issue #116 security fixes.
- PR #119 updated web development dependencies `@babel/core` 7.29.0 to 7.29.7,
  `postcss` 8.5.15 to 8.5.25, and `ws` 8.20.0 to 8.21.2. The `postcss` range
  includes source-map and prototype-hijacking security fixes; the `ws` range
  includes limits for a remote memory-exhaustion denial of service.
- The shipped workbench migrates from `react-router-dom` 7.18.0 to
  `react-router` 8.3.0. Its package now requires Node.js 22.22.0 or newer and
  React/React DOM 19.2.7 or newer, matching React Router 8's runtime contract.

## Maintenance

Tests and oversized source modules were split without changing their public
interfaces. TUI queue-depth accounting now reads the channel-local depth rather
than a process-wide gauge, and platform-sensitive process tests were made
independent of host `PATH` and timing races.

## Upgrading

No release tag or published artifact is created by these notes. Operators using
Marker HTTP must provide `--pdf-root`; restart the server after corpus changes,
and do not use `--allow-non-loopback` without supplying an external
authentication and network-control layer.
