# v1.8.0

Minor release. The cognitive metrics that v1.7.0 started producing now have a
consumer that can say no: release gates judged per cohort, a self-model that
writes its prediction before the action it predicts, and reflections that are
carried into later turns and measured for reuse rather than written and
forgotten. The learning roadmap's R0 entry gate exists as a script that can go
red instead of a paragraph. The corpus viewer renders PDFs, sandboxed. And
workflow runs finally appear on the task board.

## Upgrade notes

**Project capability manifests no longer hoist tools.** `sync-capabilities` wrote
the ambient toolchain into `.archon/project.json`, and that manifest was unioned
into every task before planning — so every task had to invoke `archon`, `bash`,
`cargo` and `python3` to be accepted, and no branch could legally declare it had
nothing to do. Env keys still hoist; tools do not. An environment key is checked
for presence and obliges no one, while a tool must be *run*. Tools already
written into an existing manifest are reported as `inert_tools` and left on disk
— a manifest only ever grows, and silently rewriting a project's file to match a
code change is not this command's business (#163).

**A declared artifact must now be a regular, non-empty file.** All four
declared-artifact checks asked `Path::exists()`, which says yes to a directory
and yes to a zero-byte file — so a fabricated deliverable could reach the run's
final report. A candidate that fails now says which: a directory rather than the
declared file, an empty file, or absent. `requiredArtifacts` also refuses prose,
oversize and control-character entries outright rather than dropping them
quietly, and an unset `${PROJECT_ROOT}` is an error rather than an empty
substitution that turns an absolute path relative. A workflow that was passing on
a directory named after an acceptance-criterion sentence will now fail (#168).

**`events.jsonl` gains a `blocking_gap_detected` kind.** A write-capable fanout
could fail with `severity: blocking` and nothing in the event stream said so, so
a run that lost an entire remediation wave presented as healthy for its whole
duration. Monitors filtering on kind should add it. The existing `stage_failed`
emission for the same call is untouched, so no consumer loses a signal it already
had, and no SDK mirrors the kind enum (#162).

**Cognitive release gates can now withhold autonomous proposals.** `CognitiveTick`
consults the thresholds before `propose_improvements`: a degraded cohort must not
be the evidence base for the agent proposing changes to its own behaviour.
Blocked checks land in `report.errors` and are persisted to the audit row, so the
audit names the segment that stopped it. `archon cognitive gate [--json]` exits
non-zero on failure. An unreadable metric store fails closed (#83).

**Garden review-band adjudication is detached.** It was awaited inline on the
session bootstrap — an LLM round-trip before the TUI starts and before you can
type. It is now spawned and detached, so nothing on the startup path waits on it,
and the timeout moves 45s → 120s precisely because it no longer bounds anything a
user is waiting on. Still off by default (`auto_adjudicate_review_band`), and the
reason has changed: not startup latency any more, but that it spends a round-trip
you did not ask for and reshapes stored memories with the answer (#122).

## Cognitive: gates, predictions and carried lessons

`metrics/thresholds.rs` sits beside `definitions.rs` and follows its rule —
bounds are compiled, and `METRIC_THRESHOLD_VERSION` must be bumped to change one,
so loosening a gate to get a release out is a reviewable diff rather than an
UPDATE nobody sees. Each bound states its derivation instead of being a round
number; the calibration ceiling is the Brier score of the constant-0.5 predictor,
so a model that fails it is worse than refusing to predict. A threshold naming a
metric no definition derives, and a formula change that would orphan the bounds
derived from it, are both detected — the second yields `DefinitionDrift`, which
blocks, because an incomparable check is not a pass.

The gate judges cohorts, not the aggregate: every segment is judged separately
and any failing one fails the gate, with the pooled figure counted as one voice
among the segments rather than the deciding one. `NotEvaluated` is distinct from
`Passed`, and a cohort under the sample floor is `InsufficientEvidence` — neither
rounded up into a pass nor used to fail a release (#83).

`SelfModelPredictionEvaluated` was a defined metric kind with zero producers and
`self_model_confidence_calibration_error` a declared threshold with no events — a
gate that could not fire. It has its only producer now, and the prediction is
written *before* `prepare_turn_request` builds the LLM request, because what makes
a comparison a prediction rather than a rationalisation is that it was recorded
first. No fact means no prediction; an absent measurement is absent, not a default
of 0.5 dressed up as one. The briefing names unmeasured domains as unmeasured
rather than omitting them, and an entirely unmeasured self-model injects nothing
at all (#80).

Reflections are injected into later turns, bounded three ways: same situation kind
only, at most three per turn, and at most three injections per reflection per
session, with the per-session count spent before the turn runs so a turn that dies
still pays. Citation and verified reuse are different claims — only a citation
*plus* a passing verification retires a reflection from the pool, because a lesson
that was mentioned and then failed has not been learned. Thinking blocks are not
scanned. `lesson_citation_rate` was keyed on `rule_injected` and was therefore a
constant 1.0 by construction; it is re-keyed to `cited`, with
`reflection_verified_reuse_rate` added beside it at the roadmap's R6 bar of 0.20
over 100 samples (#81).

## The R0 entry gate is a check, not a paragraph

The roadmap makes R0 the gate on promoting R2–R6: no behaviour-changing slice may
be promoted until findings 9, 11, 17 and 40–43 have verified closure evidence.
That evidence did not exist in any checkable form. All seven are closed in source
with a live call site and behavioural tests, and
`docs/development/r0-entry-gate.evidence` records, per finding, the closure
commits, the source anchors that must remain, the defect signatures that must stay
absent, the ordering constraints, the live call site and its tests.
`scripts/check-r0-entry-gate.sh` re-verifies every statement, and runs both as the
`r0-entry-gate` job in CI (with full history and `--require-commits`) and as step
2b of `scripts/ci-gate.sh` — an entry gate nothing runs is a document, and one
that cannot fail is decoration.

It is proven to go red against the real tree: reintroducing a removed function
fails on the defect signature, renaming a live call site fails with "live call
site gone", and removing the flag from the CI job turns the wiring test red.

One deviation matters downstream. Finding 41 shipped as five compile-time constant
rule identities rather than similarity matching, so raw user text can never reach
a rule body — but rule text no longer carries lesson provenance, and R2 and R3
must take provenance from correction records instead (#86).

## Web

The corpus source viewer renders PDFs. `pdfjs-dist` had been a declared dependency
since the workbench was scaffolded and never once imported, which is how it came
to ship a high-severity CVE for a feature that did not exist. Three controls ship
together, because the version bump alone was never sufficient: `enableScripting:
false` and `enableXfa: false` in a frozen options object, with every page rendered
at `annotationMode: DISABLE` so a document's JavaScript has no dispatch point; a
CSP whose `script-src` is exactly `'self'` and `'wasm-unsafe-eval'`, with
`object-src 'none'` closing the browser's own plugin path; and a fully local
runtime — worker, cmaps, standard fonts, wasm and colour profiles copied out of
`node_modules` at build time, since left unset PDF.js reaches for Mozilla's CDN
and the CSP would then block it.

Bytes are served by a separate `/api/corpus/source/bytes` endpoint rather than
base64 in `CorpusSourcePreview.content`, with `nosniff`, `no-store`, an attachment
disposition with a sanitised filename and its own `default-src 'none'; sandbox`;
the client fetches the buffer and never navigates to the URL. `preview_available`
becomes a `preview_mode` enum, because a boolean could only ever say "text or
nothing" — which was the bug. Non-PDF binaries render the server's stated reason
rather than a placeholder (#160).

Flagged deliberately: `web/dist` grows from 1.12 MB to 6.08 MB. The viewer is a
lazily-imported chunk fetched only when a PDF is selected, and 3.33 MB of that is
the PDF.js runtime data that lets non-embedded fonts, CJK and JPX images render
with no network access.

A web-chat attachment now reports the docs `document_id` it was ingested as.
The backend had it all along — the ingest result was injected into the model
prompt but never returned to the client, so the only party who could see the
evidence was the model. `WebChatAttachment.document_id` is `None` when the file
was never ingested, and an empty id is collapsed to `None` rather than emitted as
`""` (#164).

Seven surfaces were fetch-once under `staleTime: 10_000`, so a workflow could run
start to finish with the tab frozen at page load. Each of the nine
`WebLiveManager::record` call sites is now mapped to the surfaces its recorded
action actually wrote, three of them to nothing and saying so. Bursts are
coalesced in a 250 ms window — deliberately shorter than the server's 1 s stream
poll, so one SSE frame is never split across two flushes — and 40 events in a
window produce 6 invalidations, not 120. `workflows`, `pipelines` and `world` have
no live event and get no timer; inventing a poll would have hidden the gap rather
than reporting it (#165).

## Workflow

Workflow runs produced nothing on the task board. `raise_delegated_task` had
exactly two callers, both spawn *tools*, while workflow stages dispatch through
the V2 lifecycle — and there are two dispatch paths, not one:
`PipelineWorkflowRunner::run_stage` is the obvious one, and
`LiveV2AgentClient::run_agent_request` is the one a real decomposed run takes.
Both are wired. A stage branch is raised as a `Note`, not an `Issue`, because the
drain gate counts an issue in `in_review` as undrained and every run would gate
itself. The item is owned by an RAII guard that closes `Failed` on drop unless a
verdict was set, so none of `run_stage`'s nine exits leaks an item (#161).

Three failures behind #163 are fixed. A branch error no longer discards its
siblings' outcomes — `run_prepared_worktree_wave` did `completed.push(item?)`, so
one unrecognised `Err` aborted the collection before anything was persisted;
branch identity is now captured before the jobs consume it and results zipped back
against it, with `ControlPaused`/`ControlCancelled`, `NotificationDelivery` and
`SpecInvalid` staying fatal for reasons recorded individually. An identical
rejection now ends the repair loop instead of exhausting the budget on attempts
that cannot differ, re-offering the candidate under an explicit
`predicate_unsatisfiable_as_written` declaration. And a wave whose branches left
no trace blocks instead of walking into remediation, reading both `items` and
`outcomes` because only one of the two carries `files_changed`, `artifacts` and
`patch_landed`; a declared noop counts as a trace in its own right.

`/context` can now distinguish three quantities a user needs to tell apart when a
turn is refused for size: where the context-window figure came from, what is spent
before any conversation content, and how large the most recent request body was.
The last is banked *before* the send, because a request rejected for size never
bills an input token, so a figure taken from usage would read zero for exactly the
turn being diagnosed (#37).

## Fixes

- Two production `/tmp` fallbacks wrote to the drive root on a host where
  `home_dir()` or `HOME` is absent — agent memory under `F:\tmp\.archon\` and
  every agent git worktree under `F:\tmp\.local\share\`. Both fall back to
  `std::env::temp_dir()` now, and the gate that missed them matched `/tmp/` with a
  trailing slash, so a bare `"/tmp"` used as a fallback root slipped through
  (#156).
- The VSCode extension spawned the backend without `windowsHide`, popping a blank
  console on every connect that reads as a hung archon — and closing it kills the
  backend. Hiding it alone would have been worse, since stderr was `inherit`, so
  it is piped to an "Archon" output channel and the `exit` handler emits a line
  too: a process killed from outside writes no stderr on its way out (#159).
- Three tests mutated `ARCHON_PROV_DB_PATH` / `ARCHON_KB_DB_PATH` with no lock in
  a binary whose tests run concurrently, two of them carrying comments asserting
  the opposite. All three removed the global dependency rather than serialising
  around it. Production behaviour of both variables is unchanged (#166).
- `tradingview_snapshot_payload` read `ARCHON_TRADINGVIEW_SNAPSHOT_FIXTURE` four
  frames below the command boundary, so a test could only supply a fixture by
  mutating the process environment — and three did, clobbering each other. The
  variable is resolved once at the boundary into an explicit `SnapshotSource`; the
  documented behaviour is unchanged.
- `RecoveryLadder::next_unclassified` returned `None` unconditionally and had no
  production caller, while its one test asserted exactly that — the shape that
  makes dead scaffolding look covered. Deleted; the other 14 recovery-ladder tests
  pass unchanged.
- CI supersedes in-flight PR runs but never a run on main. `cancel-in-progress` is
  an expression rather than `true`, and that is the whole point: superseding a PR
  run saves runner time, while superseding a main run loses the only verification
  that branch will ever get.

## What this release does not close

**#154 is partly closed and stays open.** The hook-executor half is fixed: spawn
time was charged to the hook's work budget, and a passed deadline could be
overridden by an exit code, so a hook that had to be killed could report success.
Spawning now has its own budget on a blocking thread, and every phase fails closed
if the budget is gone whatever the inner future returned. Measured on a 32-core
box under the failing load: 30/30 runs failed before and 0/24 after; at sixteen
concurrent jobs, 18/64 before and 0/64 after. One shared-state instance in
`archon-trading-data` is also fixed. The remaining instances in `archon-tools` and
`archon-plugin` are not, and the measurement is recorded on the issue.

**Several R-series items are blocked on evaluation corpora, not on code.** R0
passing does not promote anything: the quantitative bars in
`docs/development/learning-roadmap-r1-r8-w5-w6.md` need runtime cohorts no script
can reach — 500 non-trivial shadow turns for R1, 200 adjudicated correction
attributions for R2, 400 adjudicated examples for R3, 500 replayable queries for
R7. The self-model calibration number shipped here is sound for gating and for
tracking movement, but its label is tool-execution outcome while the fact it
grades derives from verified reflection outcomes; making it a calibration of task
success needs reflection outcomes fed from the same deterministic label and an
evaluation corpus.

**#162 part 2 was assessed and split out** rather than half-built.
