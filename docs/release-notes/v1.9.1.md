# v1.9.1

Patch release. Prompt caching now works on every provider archon talks to,
rather than on the one endpoint whose URL it recognised. Four Bedrock models
that could not be called at all now can. Cache reads and writes are priced at
what they actually cost, instead of at zero and at par. And the debug logging
that would have shown all of this was itself inert.

Every finding below was verified against a live service, not inferred.

## Upgrade notes

**Prompt caching is emitted against endpoints it previously refused.** Archon
recognised `https://api.anthropic.com/v1/messages` and nothing else, and
*stripped* every `cache_control` directive against anything that did not match —
so a gateway that would have honoured caching was billed in full on every token
of every turn. That is safe against a gateway that would reject the field and
ruinous against one that would not, and only the operator knows which theirs is.
Declare it:

```toml
[context]
prompt_cache_strategy = "anthropic"   # auto | anthropic | bedrock | responses | automatic | off
```

Declaring the format does **not** let archon guess the limits. A gateway URL
resolves to `CachePlatform::Unknown`, which takes the strictest minimum across
every candidate stack, so a checkpoint cannot land under Bedrock's floor — where
it would be discarded in silence and billed in full. `auto` remains the default
and remains conservative.

**Every provider now declares how it caches, and a guard test enforces it.**
`cache_strategy` and `cache_platform` had trait defaults, and three providers
inherited them by accident: requests went out uncached and nothing failed.
`archon-llm` now fails to build if a new `impl LlmProvider` omits either.
`CacheStrategy::None` is still a valid answer — the test only insists that the
choice is made. The decorators are checked for forwarding too, since one of them
swallowing the call would disable caching everywhere at once while each provider
still looked correct in isolation.

**This turn's volatile system blocks move behind the message history.** Recalled
memories, the inner voice and the turn's reminders were appended to the end of
the system prompt, which put content that changes almost every turn *in front
of* the tools and the entire conversation. Every provider caches by common
prefix, so one changed memory invalidated everything behind it. They now go onto
the last user message, where archon's `<system-reminder>` content already goes.

This changes **where the model sees that text** — later, and closer to the
user's message — so it is a switch, defaulting on:

```toml
[context]
prompt_cache_reorder = true
```

On the providers that cache implicitly (GPT-5.5 and earlier, DeepSeek) there is
no breakpoint to place and this ordering is the only lever that exists.

**Cost figures will move, in both directions.** Cache reads were priced at
**zero** and cache writes folded into plain input at **1.0x**, for every model
except DeepSeek — so caching could only ever look like a saving, and a
deployment writing checkpoints it never read back showed a falling per-turn cost
while the invoice climbed. The four buckets are now priced separately from the
vendors' published multipliers of base input: **0.1x** to read, **1.25x** to
write, **2x** at the one-hour tier. Per-model rates replace the flat
Sonnet-class estimate, and regional Bedrock and Vertex endpoints carry their
**10% premium**, read from the `eu.`/`us.` prefix in the model id.

Add or correct a price without waiting for a release:

```toml
[context.model_pricing."gpt-5.6"]
input_per_mtok = 1.25
output_per_mtok = 10.0
```

**`prompt_cache_conversation = false` no longer disables everything.** It meant
"do not spend a checkpoint on the message history", but it was folded into a
single flag with `prompt_cache`, which on Bedrock and OpenAI removed the whole
directive — taking the tools and system checkpoints with it, the expensive ones,
which nobody had asked to give up.

**`RUST_LOG` now reaches the session log.** It was ignored outright in favour of
`ARCHON_LOG`, so the one knob everybody reaches for did nothing and the log
looked empty. `ARCHON_LOG` still wins where both are set. Note the log is
written by a non-blocking appender that flushes on exit, so the file stays empty
while archon is running.

## Fixes

**Dated Bedrock model ids could not be called at all.** SigV4 outside S3
requires the request path URI-encoded **twice** — once for the request line,
again for the canonical request — so the colon in
`anthropic.claude-haiku-4-5-20251001-v1:0` becomes `%3A` in the URL and must
appear as `%253A` in the signature. Archon encoded once. The failure presented
as *"The request signature we calculated does not match the signature you
provided. Check your AWS Secret Access Key"*, which reads as a credentials
problem and is not one: the same credentials worked perfectly against any model
whose id happened to contain no special characters. Four of the five models
verified in this release were unreachable before it.

**Bedrock checkpoints were never emitted.** The streaming path called the
uncached body builder, so no `cachePoint` element ever reached the wire.

**`ConverseStream` responses were decoded as text.** Bedrock returns
`application/vnd.amazon.eventstream` — a 12-byte prelude, a header block, the
payload, a CRC — with the event name in the `:event-type` **binary header**, not
in the JSON. The old code ran `from_utf8_lossy` over the frames and scanned for
a wrapper key that never exists, so every turn completed in a few seconds with
no content and no error.

**Thinking blocks were dropped on Bedrock.** Converse wants
`reasoningContent.reasoningText`; unmapped blocks were filtered out, so a
thinking-only assistant turn became `content: []`, which Converse rejects — and
that message then poisoned every subsequent turn in the session.

**Vertex discarded every system-prompt marker.** `build_claude_body` joined the
system blocks into a single string, so `cache_control` was thrown away before
serialisation while `cache_strategy` still advertised that Vertex cached. The
array form is emitted only when a marker is present, so requests that are not
caching keep the exact body Vertex has always received.

**Bedrock and Vertex model ids never matched the context catalogue.** The
catalogue is keyed `claude-sonnet-4-6`, so `eu.anthropic.claude-sonnet-4-6`
missed and the window read as unknown. Not cosmetic: the window sizes
auto-compaction.

**OpenAI cached tokens were counted twice.** OpenAI reports `input_tokens` as
the total with `cached_tokens` a *subset*; Anthropic and Bedrock report the two
as disjoint, and archon sums the buckets to get the context size. Measured on a
real ~12k prompt with 9,728 cached, archon reported **21k of context** and
charged **$0.07** where the correct figures were 10k and **$0.02** — inflating
the figure that sizes auto-compaction, and pricing cached tokens at the full
input rate *on top of* the cache-read rate, which made a working cache look more
expensive than none.

**An EC2 instance profile reported as missing credentials.** `providers status`
judged Bedrock on `AWS_ACCESS_KEY_ID` alone, but credentials resolve from the
environment, then `~/.aws/credentials`, then IMDS. A box configured the normal
AWS way — or carrying only an instance profile, which is the arrangement that
keeps a static secret off the machine — read as unauthenticated. IMDS is still
not probed by the status command, because a link-local call would stall it on
every machine that is not EC2; such a box now reports `unknown-local` rather
than a false negative.

**`ARCHON_DEBUG_LOG_DIR` did nothing.** It was parsed, stored and printed by the
environment dump, and read by nothing. The TUI and the command paths also
resolved the log directory separately, so only one of them could have been fixed
in isolation; both now share one function.

**Codex and Bedrock request bodies are logged at debug level**, alongside the
raw `cached_tokens` OpenAI reports — which distinguishes "the service reported a
miss" from "the service reported nothing", a difference the counters erase.

## Verification

Prompt caching was confirmed against live services on both authentication paths.

Bedrock, `eu-west-2`, five models spanning both minimum bands and all three id
spellings — write on the first request, read on the second, asserted against
Bedrock's own counters rather than the JSON archon sent:

| Model | minimum | written | read |
| --- | --- | --- | --- |
| `eu.anthropic.claude-sonnet-4-6` | 1,024 | 10,409 | 10,403 |
| `eu.anthropic.claude-haiku-4-5-20251001-v1:0` | 4,096 | 10,408 | 10,402 |
| `eu.anthropic.claude-opus-4-6-v1` | 4,096 | 10,409 | 10,403 |
| `eu.anthropic.claude-sonnet-4-5-20250929-v1:0` | 4,096 | 10,408 | 10,402 |
| `eu.anthropic.claude-opus-4-5-20251101-v1:0` | 4,096 | 10,408 | 10,402 |

That sweep ships as an ignored test:

```bash
cargo test -p archon-llm --test bedrock_live_cache -- --ignored --nocapture
```

Anthropic subscription OAuth under `identity.mode = "spoof"`, three turns in the
TUI on `claude-opus-5`: `cache 21/0k` then `0/18k` then `0/18k`, with the
marginal cost falling from $0.13 to $0.02 to $0.01 as the conversation grew.

OpenAI via the Codex subscription on `gpt-5.6-sol`: 9,728 tokens read back on
the second turn, which is also how the double-counting above was found.

Opus 5, Opus 4.8, Opus 4.7, Sonnet 5 and Fable 5 return `AccessDeniedException`
on the test account with **every** availability field reading
`AVAILABLE`/`AUTHORIZED` and the inference profile `ACTIVE` — an account-level
entitlement only AWS can grant. Verify with an invocation, never with the
availability fields.
